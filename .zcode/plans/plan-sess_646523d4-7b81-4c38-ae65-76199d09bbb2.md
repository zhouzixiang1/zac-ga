# 修订计划：三套代码复现论文数据 → 新文件夹开发 GA

## 两条硬性要求（本轮修订核心）
1. **前期跑通 = 复现论文数据**：ZAC 对齐 HPCA'25（数据源：仓库内 `ZAC_AE/csv/*.csv` 论文原始数据）、qmap 对齐 ICCAD'25 Table I、NEAT 对齐 DAC'26 Table 2。逐电路对数，不匹配要查因修到匹配。
2. **GA 新建文件夹独立开发**：`GA/` 目录，**不修改 ZAC 任何源码**——通过 `sys.path` 引入 `ZAC/` 的包、以 `class ZAC_GA(ZAC)` 子类覆写放置方法注入 GAPlacer；复用 ZAC 的 `.venv`(3.10) 运行。

## M0 提取论文真值表（新增，先行）
- 解析 `ZAC_AE/csv/`（technique_comp / time / fidelity_breakdown 等）→ `experiments/paper_truth/zac.csv`（18 电路的 fidelity + duration）
- 摘录 ICCAD'25 Table I（20 行：placement/routing time、重排步数、重排时长）→ `experiments/paper_truth/qmap_table1.csv`（我已读过论文全文，直接录入）
- 摘录 NEAT Table 2（9 个码：depth、#move、总距离）→ `experiments/paper_truth/neat_table2.csv`
- 验收：三份真值 CSV 就位，作为后续所有"跑通"的判卷标准

## M1 ZAC 复现（HPCA'25）
1. 冒烟：`python run.py exp_setting/test.json`（toy2，verifier 必须通过）
2. 全量（后台）：`python run.py exp_setting/repro_paper.json`（18 电路，qasm_sa_1000_reuse 配置，与 CSV 数据同源配置）
3. 对数：`experiments/compare_zac_truth.py`——新跑的 fidelity/duration vs `ZAC_AE/csv` 真值，逐电路输出 diff
- 验收：**fidelity 与 duration 与论文 CSV 一致**（确定性管线：SA seed(0)+transpiler seed 0，容差 ±0.5%，预期完全一致）；不一致则排查环境差异并修复
- 风险对策：CSV 若由 ZAC_AE 的 `gen_results.sh`/`process_data` 生成，必要时按其管线重跑核对

## M2 qmap 复现（ICCAD'25 Table I）
1. venv(3.13) + **按官方 eval 脚本的版本钉死安装：mqt.qmap==3.5.0、mqt.bench==2.1.0**（作者自己的复现配置，不用 3.8.0）；import 自检 `mqt.qmap.na.zoned`
2. 电路来源对齐论文：MQT Bench 行（graphstate 60/100、wstate 200、qft 200/500、qpeexact 200）用 `get_benchmark(INDEP)` 生成；QASMBench 行（ising 42/98、qft 18/29、bv 30/70 等 13 行）直接用 `ZAC/benchmark/hpca/` 的同名 qasm；统一预处理 transpile(cz/id/u1/u2/u3, opt3, seed0)
3. `experiments/spec_convert.py`：ZAC 架构 JSON → qmap 格式
4. 跑 Table I 的两种方法：Routing-Agnostic（=论文里的 ZAC C++ 版）与 Routing-Aware astar（论文调参 α=0.2, β=0.2, γ=5, δ=0.6；MQT Bench 大电路用论文第二组参数）+ 默认 ids
5. 指标：移植官方 Evaluator（stats() 计时；.naviz 解析重排步数与时长，cubic 运动剖面）
- 验收：**重排步数、重排时长与 Table I 逐行一致**（与硬件无关，应严格对上）；placement/routing time 为硬件相关（论文 Apple M3），只做量级与相对关系核对；对不上先查电路生成版本与参数

## M3 NEAT 复现（DAC'26 Table 2）
1. clone github.com/gcc-bug/neat → `neat/`（gitignore）；venv(3.13) + `pip install -e .`（ortools 9.10.x、stim、qiskit≥2.1 等自动装）；跑 `example/` 与 pytest
2. 跑其 evaluation 复现 Table 2 的 NEAT 列：9 个码（C4/C6/Steane/Shor/3DColor/Surface7/13/Planar7/13）的 depth、#move、总距离
- 验收：**depth 完全一致，#move/总距离一致或容差内**；求解时间仅量级核对（论文 256 线程工作站 vs 本机）
- 范围注明：NEAT 输入为稳定子校验矩阵（QEC 电路），不进 QASMBench 主对比表，作独立参照

## M4 统一评测框架
- `experiments/parse_zair.py`（ZAC/GA 侧：rearrangeJob 数=重排步数、时长、fidelity、各阶段耗时）+ `parse_naviz.py`（qmap 侧）
- `experiments/run_all.py` → `experiments/results/summary.csv`
- 验收：主对比表（ZAC / qmap-astar / qmap-ids × 步数/时长/放置时间），并与两篇论文数据交叉验证

## M5 GA 开发（新文件夹 `GA/`，不碰 ZAC 源码）
目录结构：
```
GA/
  zga/
    zac_ga.py      # class ZAC_GA(ZAC)：覆写 place_qubit_intermedeiate（必要时含 initial），注入 GAPlacer
    gaplacer.py    # GAPlacer（接口同 VertexMatchingPlacer）
    racost.py      # 路由感知代价（从 HeuristicPlacer.cpp 移植：Σ√dmax、SD+缩放、前瞻均值、γ=5/α=0.2）
  run.py           # 入口（sys.path 注入 ZAC/，其余流程与 ZAC/run.py 一致）
  exp_setting/     # ga.json 等配置
  tests/           # racost 单测 + 端到端
```
1. v1a 逐层 GA：染色体=层内"门→候选位点"分配（解码器保证合法）；fitness=routing-aware 代价；保留 ZAC 复用管线（隔离变量：只换搜索，与 A* 同构）
2. v1b：染色体加复用比特位（对齐 A* 完整决策空间）
3. 算子：swap 两门位点 / 重分配冲突组内门 / 邻居位点移动；参数默认取笔记值（population=6, iterations=8, neighbors=2, sample=24）
4. 增量评估：兼容组缓存（Python 有序结构模拟 std::map）
- 验收：toy+3 电路端到端 verifier 全过；racost 单测全绿；GA 与 ZAC 原版在同一电路上除放置阶段耗时外其余指标可解释

## M6 全量实验
- 18 电路 × {ZAC, qmap-astar, qmap-ids, GA-v1a, GA-v1b} 主表
- 消融（去 SD / 去前瞻 / 去 γ）+ 预算扫描（pop/iter 6×8→32×64 的 placement time vs 步数 Pareto）
- 成功标准：GA 步数改善接近 astar 的 −17%（vs ZAC），放置时间快 ≥10×
- 可选 v2：跨层全局染色体（超越逐层 A* 近视性的论文增量点）

## 工程约定
- `.gitignore` 追加 `qmap-main/`、`neat/`、新建 venv；ZAC 目录零改动；GA 全部在 `GA/` 内提交
- venv：ZAC/GA 用现有 `.venv`(3.10)；qmap、NEAT 各建独立 venv(3.13)

## 主要风险
- ZAC 复现偏差：CSV 与当前代码/依赖有漂移 → 以 ZAC_AE 的 gen_results.sh 管线核对；requirements 已与论文一致（qiskit 1.2.4）
- qmap Table I 的 MQT Bench 电路版本漂移 → 钉死 mqt.bench==2.1.0（官方 eval 同款）；仍不符则从论文 Zenodo 动画数据集核对电路
- NEAT 依赖窗口（ortools<9.11、qldpc<0.2.1）→ 手动 pin 安装
- 跨编译器"重排步数"口径 → M4 文档化对齐
- GA 代价移植无 C++ 对照 → 三段式单测 + 论文公式对应 + toy 端到端 sanity
