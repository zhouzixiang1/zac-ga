# Repository working conventions

- The repository root is this `zac/` directory. Work on `main` unless the user requests another branch.
- This root is the only maintained project. `archive/` contains local historical material, is excluded from Git, and must not be used as the default source or experiment output. See `docs/ARCHIVE_POLICY.md` and the relocation index before recovering an old path.
- The active Chinese IEEE manuscript is `IEEE_conference_template/paper_zh.tex`. Edit this in-repository copy; the desktop `IEEE_conference_template_upgrade` directory and ZIP are retained snapshots, not active editing targets.
- Preserve existing uncommitted changes; the author may edit the manuscript concurrently.
- Keep `IEEE_conference_template/` minimal: manuscript TeX, required figures/data, bibliography, class/style, one README and `build/`. Python generators/checkers/tests belong in `scripts/paper/`; writing notes, JSON metadata, retired figures/tables and template references belong in `docs/paper/`. Use `scripts/paper/paper_paths.py` for support paths; do not recreate the former `writing/`, verifier scripts or JSON files inside the manuscript source tree.
- The English counterpart is `IEEE_conference_template/paper_en.tex` with same-named files in `sections_en/`. Keep its claims, formulas, citations and data aligned with the Chinese source. Use `make paper-en` and inspect both rendered versions after bilingual edits; English outputs belong in `IEEE_conference_template/build/paper_en/`, targeting six body pages plus one references page; Chinese follows the same compact structure with natural pagination.
- Use `IEEE_conference_template/build/overleaf-sync/` for the Overleaf export and Git checkout. Inspect remote changes before exporting; never force-push or overwrite unmerged online edits. Adapt only registered figure/data input paths for the cloud project and leave desktop TeX unchanged. Validate full evidence packages locally, but export only their required TeX files; do not upload Python, JSON, CSV, tests or writing notes. The cloud README gives Overleaf-specific compilation instructions.
- Put newly generated compilation outputs in `IEEE_conference_template/build/`: paper PDF, figure PDF, LaTeX auxiliaries, QA and previews in `IEEE_conference_template/build/paper_zh/`; CMake/CTest and wheel outputs in `IEEE_conference_template/build/native/`. Use the root Makefile rather than compiling into source directories.
- Do not recreate a root `build/` directory or compatibility symlink. See `docs/BUILD_OUTPUTS.md` for the author-requested migration, preserved old caches and frozen-protocol resume limits.
- Do not relocate or delete experiment build artifacts, installed environments, or frozen evidence as part of build cleanup. The author-authorized September 2026 archive migration is separately recorded; it does not authorize future blanket cleanup. Experimental data are not disposable build output.
- `ZAC_zzx/results/paper_zh_v2/` is the authoritative accepted evidence. Do not rerun experiments, regenerate its data, change baselines or modify frozen native sources for a manuscript-only task.
- Current initialization and horizon studies remain in `ZAC_zzx/results/`; their lightweight protocols/scores are Git-visible, while raw traces/logs and the full preservation seal remain local. Keep failed and incomplete runs; do not promote them to accepted main results.
- Preserve TikZ/PGFPlots sources and frozen inputs, including retired `figures/data/` files now stored under `docs/paper/supplementary/` (see `docs/paper/relocation-20260913.json`). The framework figure (current Figure 2, source `overall_framework.tex`) is built separately for each language before main-paper compilation; a failed figure build must not reuse a stale PDF.
- After manuscript edits, run `make paper` and relevant paper tests, inspect the rendered PDF and check page count, references, overfull boxes and numerical consistency. The September 14 compact-layout target is six English body pages plus one references page; Chinese pagination is natural.
- Keep the repository map and manuscript README aligned with actual paths. Distinguish local commits from a verified push; do not claim remote synchronization without checking the remote branch.
