\section{Method}
\label{sec:method}
\label{sec:formulation}

\subsection{Overall Framework}

GA-LK compiles quantum circuits into atom-transport and gate-execution instructions that satisfy zoned-architecture constraints. Compilation proceeds through gate scheduling, initial placement, layer-wise joint placement, routing and scheduling, and code generation, as shown in Fig.~\ref{fig:overall-framework}. Gate scheduling determines which interactions can share a two-qubit layer. Initial placement assigns storage traps to atoms. Layer-wise placement selects entanglement sites for gate participants and decides whether other atoms return to storage and where they go. Routing and scheduling convert position changes into executable batches; code generation records instruction dependencies and execution times.

Look-ahead guides two stages. Initial placement compares the effects of storage layouts on the first few gate layers. Dynamic placement estimates subsequent execution losses from the positions, occupancy, and clocks produced by each candidate after the current layer. During search, candidates undergo the same constraint checks used in routing. Gate-site and residency choices can therefore be optimized jointly using executable transport costs.

\subsection{Gate Scheduling}

The compiler preserves same-qubit dependencies in the input circuit and assigns two-qubit gates to their earliest executable layers. Gates within a layer share no atoms; layers exceeding the entanglement-zone capacity are split. For two-qubit gate sets that permit reordering, interaction-graph edge coloring follows the baseline scheduler: gates on edges of the same color share a layer~\cite{lin2025zac}. This stage determines logical parallelism. Transport and resource dependencies determine the actual execution times later.

Single-qubit gates are grouped into execution blocks according to their preceding two-qubit gates. Gates without a two-qubit predecessor appear before the first layer. Fig.~\ref{fig:overall-framework}(a) and (b) use RY, RZ, and U gates for single-qubit operations and CZ gates with control dots for two-qubit interactions. Scheduled single-qubit gates still act on the atoms specified by the input circuit, at locations given by the mapping at execution time. Let $L_\ell$ denote the $\ell$th two-qubit layer and $\mathcal G_\ell$ its gate set. Subsequent placement follows this fixed layer order.

\subsection{Look-Ahead-Aware Initial Placement}
\label{sec:initial-placement}

The initial layout determines the storage traps from which atoms depart, affecting their first entry and early inter-layer transport. We start from the layer-weighted simulated-annealing layout~\cite{lin2025zac}, retain it, and generate alternatives by swapping the storage positions of a few atoms. These swaps preserve the occupied trap set, with at most one atom per trap. The candidate pool is fixed before evaluation and does not change with the look-ahead horizon.

For each candidate, the compiler constructs placement and routing for the first few two-qubit layers, accumulating trap-transfer, idle-excitation, and coherence losses. This rollout uses the same current-layer optimization policy without recursively invoking multilayer look-ahead. Let $H_{\rm init}$ count the layers considered after the first layer, and let $h_{\rm init}$ be the actual count limited by the remaining circuit. An initial mapping $\pi$ is evaluated as
\begin{equation}
J_{\rm init}(\pi)=
\sum_{d=0}^{h_{\rm init}}\rho^d\,\Delta C_d(\pi),
\qquad h_{\rm init}\le H_{\rm init}.
\label{eq:initial-lookahead}
\end{equation}
Here, $\Delta C_d$ is the incremental negative log fidelity loss incurred through layer $d$, and $\rho$ is the layer-distance decay factor. Each increment is the difference between successive cumulative losses for the same candidate. Single-qubit gates and their timing are included according to dependencies. Evaluation stops after the last gate layer in the window; no additional return is scheduled if the circuit is unfinished.

Initialization selects the feasible layout with the smallest $J_{\rm init}$, resolving ties by fixed candidate order. With $H_{\rm init}=0$, only the first two-qubit layer is evaluated; a positive horizon includes the execution costs of subsequent layers. The additional initialization experiment uses four shared candidates, $\rho=0.7$, and a 32-evaluation main-search budget per layer. After selecting the initial mapping, atom positions and execution times are reset to the circuit's starting point for full compilation.

\subsection{Joint Optimization Within Each Layer}

Optimization for each two-qubit layer jointly handles entry placement and inter-layer residency. Let $s_\ell$ contain the atom positions, trap occupancy, and execution clocks at the start of the current optimization step. Executing the target layer and its associated single-qubit gates produces $s_{\ell+1}$. Let $\mathcal Q$ be the atom set, and let $\mathcal S$ and $\mathcal E$ be the storage- and entanglement-zone trap sets, respectively. Mapping $\pi$ assigns each atom a trap and satisfies $\pi(q)\ne\pi(q')$ for distinct atoms, preventing shared occupancy.

\subsubsection{Joint Encoding and Genetic Search}

Target gate sites and resident atoms compete for entanglement-zone space. Separate decisions can leave residents blocking better gate sites or select sites that require unnecessary returns. GA-LK encodes both choices in one chromosome:
\begin{equation}
\mathbf x_\ell=
(z_{\ell,1},\ldots,z_{\ell,m},
 b_{\ell,1},\ldots,b_{\ell,k}).
\label{eq:chromosome}
\end{equation}
Here, $m$ is the number of gates in the current layer. Gene $z_{\ell,j}$ selects the gate-site pair and the orientation of the two participants for gate $j$. The $k$ atoms requiring residency decisions use $b_{\ell,i}=0$ to remain in the entanglement zone and $b_{\ell,i}=1$ to return. Decision set $\mathcal D_\ell$ usually contains entanglement-zone atoms absent from the current layer. For a single-gate layer, participating atoms may also be considered for in-zone adjustment or temporary relocation through storage. Fig.~\ref{fig:joint-ga}(a) relates the gate-site encoding to the return decision and storage assignment for $q_3$.

Search starts from diverse seeds, including all-resident, all-return, and physical-greedy solutions. Crossover acts separately on the gate-site and residency segments. Mutation reselects gate sites, flips residency bits, or jointly changes conflicting variables from both segments. Offspring pass occupancy and capacity checks before evaluation; better individuals form the next generation~\cite{holland1975adaptation}. Duplicate encodings reuse cached evaluations. When budget permits, bounded local refinement improves the best candidate. Small encoding spaces use enumeration with the same candidate decoder and objective as genetic search. Fig.~\ref{fig:joint-ga}(b) shows these two solver paths.

Search stops when the evaluation budget is exhausted, the generation limit is reached, or several consecutive generations yield no improvement. Table~\ref{tab:solver-bounds} lists the default budgets and reductions for deep circuits. Complete enumeration covers the specified bounded encoding space. Genetic search seeks better solutions within its budget without enumerating every position combination.

\subsubsection{Routing-Aware Gate-Site Selection}

A gate-site gene selects both endpoints and the transport needed to reach them. If one participant already occupies a suitable gate site, a candidate can leave it in place and move only its partner. When both must move, the candidate jointly selects a gate-site pair and orientation. Available sites must satisfy entanglement-zone geometry, capacity, and single-atom occupancy constraints. Narrow layers in deep circuits first consider a bounded, distance-ordered gate-site domain. The full domain is restored if no feasible solution is found.

Candidates are decoded in execution order. Returning atoms and gate-site blockers first receive storage locations to release the target sites. Target-layer participants then enter the zone or move within it, as shown in Fig.~\ref{fig:joint-ga}(c). Necessary temporary relocations also incur trap-transfer and time costs, which are included in the candidate loss. Each phase forms trajectories from current occupancy, checks AOD row--column relationships and unintended intersections, and constructs executable parallel batches. A geometrically closer gate site can therefore be rejected if it requires more sequential transport.

\subsubsection{Residency and Return Storage Sites}

Residency saves round-trip trap transfers but exposes atoms to Rydberg excitation in intervening layers where they do not participate. Returning to storage avoids this loss, with benefits that depend on the return distance and the next entry path. Residency genes let the search compare these choices under the same gate-site assignment, rather than making irreversible decisions atom by atom.

For a given chromosome, returning atoms still need specific storage traps. Each atom receives at most six candidate sites near its current entanglement site, initial storage site, and future partners. Linear assignment and Murty branching~\cite{murty1968assignment} generate the first $K$ distinct storage-site assignments, denoted by $a_\ell$. Injective matching prevents multiple returning atoms from selecting the same storage trap. Each assignment and chromosome form a complete candidate. A location-based proxy cost generates this bounded candidate set, but final selection uses the candidate's execution loss.

\subsubsection{Current Loss and Multilayer Look-Ahead}

For a fixed circuit, gate counts are unchanged, and placement primarily affects trap-transfer, idle-excitation, and coherence losses. Following~\eqref{eq:fidelity}, the incremental cost of completing the current layer is
\begin{equation}
\begin{aligned}
C_\ell^{\rm cur}={}&-\Delta N_{\rm tran}\log f_{\rm tran}
-\Delta N_{\rm exc}\log f_{\rm exc}\\
&+\sum_{q\in\mathcal Q}
\log\frac{1-t_q^{-}/T_2}{1-t_q^{+}/T_2},
\end{aligned}
\label{eq:current-cost}
\end{equation}
where $t_q^{-}$ and $t_q^{+}$ are the accumulated idle times before and after the transition, respectively. Transport duration follows the executable batches, and single-qubit gates update timing according to dependencies. Candidates returning the same number of atoms can thus incur different costs because their storage sites and routing groups differ.

Multilayer look-ahead starts independently from each candidate's $s_{\ell+1}$. The predictor processes future gate layers in order and selects unassigned legal gate sites. When nonparticipating atoms block sites or paths, they move to available storage sites before gate participants enter. Each predicted layer updates positions, occupancy, and clocks, so the next layer uses positions produced by the preceding predicted layer. Gate-site selection considers both participants' transport distances and the return distances of blocking atoms, with fixed-order tie-breaking. If joint entry is infeasible, bounded temporary relocation and then atom-by-atom entry are tested.

Suppose $h_\ell$ future layers are predicted, with incremental loss $\widehat C_{\ell,d}$ at layer distance $d$. Each increment includes excitation of nonparticipants, entry and temporary relocation of participants, and movement of blockers. The finite-horizon objective is
\begin{equation}
J_\ell=C_\ell^{\rm cur}
+\sum_{d=1}^{h_\ell}\alpha\rho^{d-1}\widehat C_{\ell,d}
+\alpha\rho^{h_\ell-1}\Phi_\ell .
\label{eq:lookahead-cost}
\end{equation}
The parameter $\alpha$ scales future costs, while $\rho$ discounts them with layer distance. Terminal term $\Phi_\ell$ estimates feasible return losses for residents absent from the window's final layer, avoiding a simple deferral of costs beyond the horizon. This estimate is not executed as a current instruction. At zero horizon, both the sum and terminal term are zero.

Prediction depth is limited by the remaining layers, maximum horizon $H_{\max}$, resource caps in Table~\ref{tab:solver-bounds}, and a decay threshold. The main configuration is $(H_{\max},\alpha,\rho,\epsilon)=(8,0.5,0.7,0.05)$; layers with weight $\rho^{d-1}<\epsilon$ are not expanded. The two candidates in Fig.~\ref{fig:physical-lookahead}(b) leave different starting positions for the next interaction. Atom $p$ has a shorter entry path under candidate $B$, but the benefit also depends on routing groups and critical batch durations, which the layer-wise evaluation accounts for together. Fig.~\ref{fig:physical-lookahead}(c) gives the layer-distance weights.

\subsubsection{Candidate Selection}

Prediction error can prevent a larger current loss from being recovered in later layers. Candidate selection uses a feasible low-current-loss solution as a reference. An alternative is admitted only when predicted future savings sufficiently compensate for its current-cost increase. Specifically, the increase must be at most $\eta=0.25$ of the predicted future savings, and total objective $J_\ell$ must not exceed the reference value.

The reference also accounts for beneficial residency. For atoms reused within the visible window, the solver compares the loss of remaining until the next use against a round trip through storage. Atoms with cheaper residency receive priority when capacity and mandatory-return constraints permit. This residency priority is disabled at zero horizon. The solver first considers candidate groups that return fewer such atoms, makes bounded local adjustments to their gate sites, and selects a low-current-loss reference. Admitted candidates are ranked by $J_\ell$, breaking ties by batch count, rearrangement time, transport distance, and finally fixed encoding order. If every future rollout is infeasible, selection falls back to executable current-layer cost. Algorithm~\ref{alg:solver} summarizes the procedure.

\begin{algorithm}[t]
\caption{Joint Optimization of One Two-Qubit Layer}
\label{alg:solver}
\small
\begin{algorithmic}[1]
\Require Current mapping and clocks $s_\ell$, target layer $\mathcal G_\ell$, future gate layers
\Ensure Selected gate sites, residency decisions, and executable rearrangement batches
\State Build gate-site and residency domains; generate initial candidates
\While{unevaluated encodings remain and the search budget is not exhausted}
  \State Take encoding $\mathbf x_\ell$; generate the first $K$ injective storage-site assignments
  \For{each storage-site assignment $a_\ell$}
    \State Form return, temporary-relocation, and entry paths; update occupancy in sequence
    \If{executable batches satisfy AOD and occupancy constraints}
      \State Compute current loss $C_\ell^{\rm cur}$ and resulting state $s_{\ell+1}$
      \State Predict future layers from $s_{\ell+1}$; compute $J_\ell$
      \State Store the candidate, current batches, and prediction feasibility
    \EndIf
  \EndFor
  \State Enumerate the next encoding or generate offspring by selection, crossover, and mutation, according to the search-space size
\EndWhile
\State Refine evaluated candidates locally within bounds; determine the reference
\State Select a candidate using the current-cost bound and finite-horizon objective
\State \Return Selected current execution batches and $s_{\ell+1}$
\end{algorithmic}
\end{algorithm}

\subsection{Routing and Scheduling}

Routing and scheduling convert candidate position changes into executable batches satisfying AOD constraints. Each atom trajectory is a conflict-graph vertex. An edge joins two trajectories if they violate the row--column relationships in~\eqref{eq:aod-relations} or their joint activation creates an unintended intersection over a stationary atom. DSATUR coloring~\cite{brelaz1979coloring} supplies initial groups: same-color trajectories share a batch, and different colors execute separately, as in Fig.~\ref{fig:physical-lookahead}(a). Candidate evaluation invokes this routing process; conflict checking does not begin only after placement is selected.

Each same-color group is also checked for source-trap release, destination occupancy, and AOD capacity. Groups failing these collective constraints are split further. If an individual trajectory violates static occupancy or unintended-intersection constraints, its path is changed or the candidate is rejected. The scheduler sets start times from dependencies on atoms, SLM traps, AODs, and Rydberg operations, ensuring a source trap is released before another atom uses it. Rearrangement time at a layer boundary is
\begin{equation}
T_\ell^{\rm rr}=\sum_{b=1}^{B_\ell}
\max_{\nu\in\mathcal B_{\ell,b}}\tau(\nu),
\label{eq:rearrangement-metrics}
\end{equation}
where $B_\ell$ is the batch count, $\mathcal B_{\ell,b}$ contains the trajectories in batch $b$, and $\tau(\nu)$ is a trajectory's duration. The longest trajectory determines batch duration, which is why gate-site optimization must account for parallel grouping.

A C++17 kernel implements candidate decoding, storage-site matching, conflict grouping, and future-layer prediction, caching repeated position relationships and candidate evaluations. Pairwise trajectory-compatibility checks scale quadratically with the number of trajectories. The budgets in Table~\ref{tab:solver-bounds} control per-layer cost by bounding candidates, assignments, and predicted layers. The public code repository provides the complete implementation and parameter settings.

\subsection{Instruction Generation and Output}

Compilation results use ZAIR~\cite{lin2025zac}. The initial mapping is recorded in \texttt{init}, single-qubit gates in \texttt{1qGate}, and two-qubit gates in the same entanglement zone in \texttt{rydberg}. Atom transport is encapsulated in \texttt{rearrangeJob}. Each rearrangement job specifies atom labels, source and destination traps, and an AOD identifier. It expands into three lower-level operations: \texttt{activate}, \texttt{move}, and \texttt{deactivate}, which transfer atoms into mobile optical traps, transport them, and release them, respectively. Fig.~\ref{fig:zair-output} lists the principal output fields.

Location fields retain atom labels and SLM trap sites; row and column fields specify AOD beam identifiers and coordinates. Common identifier, timing, and dependency fields are omitted to emphasize the structure; the complete output includes them.}
  \label{fig:zair-output}
\end{figure}

Code generation preserves the correspondence between gate dependencies and position changes. Single-qubit \texttt{locs} use atom positions at execution time, not their initial locations. The \texttt{rydberg} instruction records target gates and the entanglement-zone identifier. Rearrangement jobs record their internal operation order and start and end times. After all gate layers, terminal returns follow the compilation flow, and the complete sequence is emitted. An independent verifier checks gates, occupancy, and AOD constraints and computes fidelity and rearrangement metrics from that sequence. Evaluation thus uses the same executable instructions delivered by the compiler.
