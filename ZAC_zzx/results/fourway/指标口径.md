## 一、对比的四方法

| 简称 | 是什么 | 关键配置 |
|---|---|---|
| ZAC原始 | HPCA'25 ZAC 原版编译器（SA 初始放置 + 点名放置 + MIS 路由） | 冻结真值 repro_fixed 同款 |
| ICCAD | MQT-QMAP 3.5.0 zoned 编译器（ICCAD'25 路由感知方法） | astar(RoutingAware) 优先、失败或 >300 门电路回落 agnostic(RoutingAgnostic)；600s/300s 超时 |
| 遗传(无前瞻) | ZAC_zzx：驻留不放回 + 每轮 GA 门位搜索 + 分相位图着色适应度 | γ0=0（前瞻锚点项归零），GA 初始布局 init_engine=ga |
| 遗传(前瞻) | 同上 | γ0=0.5（默认），GA 初始布局 |

三方同架构（ZAC repro 硬件规格）、同一判分模型。

## 三、四个指标的定义（每个方法怎么算）

### 1. 保真度（越大越好，满分 1）
同一五项模型同判：
`F = 0.9997^n1q × 0.995^n2q × 0.999^(2×搬运人次) × Π(1−idle/T_coh)`
- ZAC/遗传：判分器 fidelity JSON 的 cir_fidelity
- ICCAD：同公式对其 NA 码直算（`qmap_score.py`）

### 2. Rearr. Steps 重排步数（越少越好）= ICCAD'25 Table I 的 Num. Rearr. Steps 口径
一次完整 AOD 重排循环（load→move→store）计 1 步：
- ZAC/遗传 = 指令流里 rearrangeJob 条数（activate+move:big+deactivate，与 load/move/store 一一对应）
- ICCAD = NA 码 load…store 作业数
- 口径核验：qmap 侧计数对论文 Table I 逐位复现（seca 112 步=112，12/15 行精确一致）；全产物 26 万班次零空班（无虚计数）

### 3. move 时间（越少越好）= 纯搬运执行时长，不含门时间
- ZAC/遗传 = Σ 各 rearrangeJob 的 (end_time − begin_time)
- ICCAD = Σ 各作业 (2×15μs + √(dmax/0.00275))

### 4. 编译时间（越少越好）= 电脑求出该解的耗时
- ZAC/遗传 = time JSON 的 total（调度+放置+路由流水线实测）
- ICCAD = transpile+compile 实测毫秒（不含 Python 启动）

## 五、四条主要结论

1. **执行质量**：遗传两变体在两套数据集的保真度/Rearr.Steps/move 时间全部第一（步数 −25%~−44%，搬运时间 −15%~−40%）；ICCAD 执行指标在大规模上甚至不如 ZAC 原版（1.065~1.072）。
2. **前瞻消融**：γ0=0 与 γ0=0.5 全指标持平——收益来自结构部件（驻留+分相位着色+GA 门位搜索），不来自前瞻锚点项。
3. **编译时间**：ZAC 的 SA 占编译 97-98% 但邻域生成器有两处缺陷（行移动死代码、new_c 误用 old_r）；换 GA 初始布局后 hpca 237s→17s（14×）、套件公共集 1122s→194s（5.8×），质量持平。对 ZAC 编译比 1.02×→0.056×。
4. **ICCAD 的定位**：编译最快（C++，154 例合计 28s）且可编译性最强（实测 astar 到 22.4 万门 94.6s 近线性，纠正"大规模只能 agnostic"的误传）；代价是执行质量。

## 六、诚实边界

- GA 初始化在 13 个贴超时线的边界电路（771~3089 门）翻车（成功数 119→106）：初始布局目标只有会合距离、缺"批次对齐项"（存储列序 vs 首进场目标列序的逆序对数），v1.1 第一优先级。
- ICCAD 编译仍快 3.5~20×（C++ vs Python）；22 万门只有它编得动（zzx 最深成功案例 15.4 万门窄层 34s）。
