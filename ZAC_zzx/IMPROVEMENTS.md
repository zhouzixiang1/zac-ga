# ZAC_zzx 改进说明：相对 ZAC 改了什么、为什么、效果如何

> 本文按最初提出的三个改进点组织：**①按 2q 门拆批次；②可以选择不放回
> （激发区的原子只要不影响后续可以一直放着）；③放置引入图着色提供引导**。
> 每个点都给出：ZAC 原版怎么做（代码锚点）→ ZAC_zzx 怎么做 → 为什么 →
> 实验证据。配套的正确性装置与全部实验数据附后。
>
> 总成绩：**18 电路 duration geomean = ZAC 的 0.867**（ZAC_new 此前最佳 0.959），
> 验证器 8 查全绿，编译全套 237s。

---

## 0. 背景：ZAC 原版的三块短板

ZAC 的流水线（六道工序）：ASAP 调度 → 复用点名 → 初始布局(SA) → 门放置
(匹配) → 路由分批(MIS 剥离) → 搬运展开/ZAIR。对照"宿舍-车间-摆渡车"模型：

| # | 短板 | ZAC 的行为 | 代码锚点 |
|---|---|---|---|
| 1 | 轮次与搬运耦合不清 | 每轮做完门**全员强制回宿舍**，下轮再全员接回；每轮白付两趟车 | `vmplacer.py:347`（激发区原子除复用名单外一律放回存储） |
| 2 | 只有"下一层马上用"才留 | 复用判定只看相邻一层（二分图匹配），跨轮驻留不存在 | `zac.py:256-305` collect_reuse_qubit |
| 3 | 放置看不见批次 | 门放置 = 纯距离最小权匹配（√d1+√d2+√前瞻），"要发几趟车"是路由贪心剥离的副产品，没有任何阶段对它负责 | `vmplacer.py:165` place_gate、`router.py:182` maximalis_solve |

实测数据（ZAC 真值 18 电路）：**回程搬运占总时长的 38.9%-54.2%**
（wstate 54.2%、bv_n14 45.5%、ghz_n78 42.8%、qft_n18 41.8%）——这就是
"不放回"要抽干的水池。

## 1. 改进一：按 2q 门拆批次（轮次体系）

### 做法

**轮次（round）= ASAP 调度产生的一层 2q 门**（每层内门互不共用比特，
每轮执行一次 rydberg 激发）。这个分层 ZAC 现成就有（`scheduler.py:53`），
ZAC_zzx 保留它作为整个编译的工作单元，并把三件事严格绑定到轮次上：

1. **每轮一次门执行**：本轮所有 2q 门同时开激光（`process_gate_layer`）；
2. **1q 门挂靠父层、在座位上执行**：单比特门跟在它的父 2q 门那一轮的
   激发之后执行，原子坐在哪就在哪做，**不为 1q 门产生任何搬运**
   （`router.py:426-441` 的既有机制，实测流内 1q 门位置在激发区/存储区均有）；
3. **搬运批次在轮内组织**：每轮两个搬运相位——去程相（入区腿，含区内
   换座）与回撤相（回程腿，驻留模式下大多数为空）。

### 为什么

这正是 ZAP 论文 ASAP-Separate 分离调度的结构（用户笔记 :181-189）：
2q 门优先排满 Rydberg 阶段、1q 门填空——避免 Joint 模式"刚搬回宿舍又
要搬回来"的病。ZAC 的分层天然满足"轮次只由 2q 门定义"，ZAC_zzx 把它
显式化并让所有后续决策（驻留、放置、分批）都以轮次为单位对齐。

### 与 ZAC 的差别

ZAC 虽然也逐层处理，但它的"层"只是调度输出；ZAC_zzx 把轮次变成
**决策的坐标系**：每个边界（轮 L 结束 → 轮 L+1 开始）跑一遍驻留决策，
每个轮次跑一遍联合放置搜索（见改进二、三）。

## 2. 改进二：可以选择不放回（驻留）

### 决策模型（每个边界，激发区每个原子）

| 原子身份 | 默认 | 触发 RETURN 的条件 | 实现 |
|---|---|---|---|
| 轮 L+1 参与者 | **STAY**：入区腿 = 区内短移到门位 | 搜索可决定回 | 决策基因/解析规则 |
| 非参与者、有后续使用 | **STAY**：原位闲放，**0 条搬运腿** | 容量阀/搜索 | 同上 |
| 死驻留者（后续无 2q 门） | **STAY**（判分模型 idle 项=1，闲放零代价） | 仅容量压力 | `resident.py` decide_lazy |
| 挡路者（座位被下一轮门位需要） | — | **强制 RETURN**（E2） | 硬排除+逐出 |
| 容量不足（保留座+2×门数 > θ·区内容量） | — | 按下次使用轮次降序强制 RETURN | 容量阀 |

**RETURN 的落位不是"回原位"那么简单**——按笔记三方案（:123-131）箱式化后
做最小权匹配（`resident.py match_return_sites`）：

| 方案 | 含义 | 省什么 |
|---|---|---|
| C1 原位族 | mapping[0] 原位 ± 自由位箱 | 保证可行（原位被占时箱内还有位） |
| C2 就近族 | 当前激发区座位最近的存储位 ± 箱 | 省本次搬运 |
| C3 伙伴族 | 下次搭档位置附近 ± 箱 | 省未来搬运 |

匹配代价 = √d(激发区座位→候选位) + α·√d(候选位→下次使用锚点)，
与 ZAC 回位放置（`vmplacer.py:491`）同一本账。

### 为什么"不放回"在 ZAC 框架里几乎免费

ZAC 的回程代码（`router.py:98-102`）本来就**只搬"落位≠目标"的原子**——
所以只要放置端把边界映射写成"留在原地"，回程就自动不搬。ZAC_zzx 的
改动集中在三处（`zzx/zplacer.py` ResidentPlacer + `zzx/zac_zzx.py`）：

1. **重写轮循环**（先定下一轮门位、再做边界决策，与原生编译器同构：
   门赢、闲人让路），产出与 ZAC 完全同构的映射流（长度 2n+1，契约断言强制）；
2. **中和复用机制**（ZAC 的"只留一层"复用点名与驻留决策互斥，同时开会
   座位双订）；
3. **路由回撤相扩展**：搬运对象从"本轮门原子"扩为"所有有位置增量的
   原子"（闲住驻留者的回撤腿也要发车），并给非参与者的依赖账本打补丁
   （压到本轮门指令之后，防与激光并行——审计实证的洞）。

### 实验证据

- **决策分布：STAY 2630 / RETURN 0**——GA 搜索自己也学到"永不回撤"
  （与原生编译器 K5 同构）：在判分模型下回撤的 2 条腿永远买不回收益，
  驻留的全部价值兑现为门位自由度；
- qft_n29 批数 401→217、knn 161→88、seca 109→52——搬运批次的塌缩
  直接来自回程相的消失与去程腿的减少；
- ising_n42 保真度 0.470→0.512（+9% 相对）：搬运人次下降使转移损耗
  0.999^(2×人次) 机械性改善。

### 发现的深层问题（记录在案）

ZAC 的 **site 依赖账本只记"离开"、从不记"到达"**。原版无害（每个到达
都在同轮内配对离开），驻留模式让原子"到达后一直坐"，账本盲区变成真
双占（ising/qft 宽层实测 8-58 处）。且同相位内"B 到达 A 的座位"在账本
体系里原理上无法排序（到达作业先于离开作业发射）。ZAC_zzx 从构造上
禁绝：菜单硬排除所有他人座位 + `_repair_placements` 终检安全网。

## 3. 改进三：放置引入图着色引导

### ZAC 的盲区

门放置 = 最小权完美匹配，边权纯距离。"两个门各选某工位会冲突、要多发
一班车"是决策间的**二次交互项**，匹配的边权表达不了；批数于是成了路由
贪心剥离的副产品。ZAC_new 已把"要几批"（冲突图色数 χ）放进适应度，
但它每轮回宿舍，且适应度只看去程。

### ZAC_zzx 的做法：GA + 分相位着色适应度

**联合染色体**（每步一次搜索，`zzx/zplacer.py _ga_step`）：

```
染色体 = [每门菜单下标基因] ∪ [有后续使用的非参与者 0=STAY / 1=RETURN 基因]
```

**分相位着色适应度**——两个时间窗（去程相/回撤相）**各自建冲突图、
各自着色**，因为它们串行执行、跨相冲突边没有物理意义：

```
F = w_batch·(χ(回撤腿) + χ(入区腿))          ← 第 1 层：精确，批数下限进目标
  + Σ√dmax(回撤色类) + Σ√dmax(入区色类)      ← 每批时间 = √批内最长腿
  + γ0^轮距 · √d(决策后位置, 下次使用锚点)     ← 第 2 层：前瞻（锚点=搭档位置投影）
```

- `w_batch=1.57` = 每批 2×15μs 固定开销的 √μm 当量；
- 驻留者的下次使用锚点：搭档在区内→其最近存储投影，在存储→原位
  （镜像 ZAC `vmplacer.py:420` 的投影规则）；
- 菜单 = 钉扎窗 ∪ 全展开集（硬排除他人座位），食堂顺延解码 + 预扩容；
- GA 骨架 = ZAC_new 引擎 A（种群 6 × 迭代 8 × 采样 24，zeros 热启动），
  类型感知邻域（门位基因 ±1/重抽，决策基因翻转）。

### 为什么必须有搜索层（消融证据）

| 放置策略（4 电路冒烟） | ghz | bv | ising | qft | geomean |
|---|---|---|---|---|---|
| 不钉扎（自由匹配） | 1.118 | 1.137 | 0.921 | 1.341 | 1.115 |
| 钉扎（驻留者不动） | 1.533 | 1.372 | 0.815 | 0.763 | 1.095 |
| 钉扎+偏移罚 | 1.533 | 1.372 | 0.815 | 1.198 | 1.197 |
| **GA 搜索（逐门定夺）** | **1.107** | **1.146** | **0.647** | **0.799** | **0.867** |

链式电路钉死则新原子家门逐轮走远（入区腿 157→250μs/轮线性上涨），
不钉则门位落在折中点逐轮漂移——**解析规则顾此失彼，取舍必须逐门搜索**，
这就是 GA 层存在的直接证据。A1（解析）1.081 → A3（GA）0.867 也是同一结论。

### 反直觉发现（诚实记录）

- **γ0 前瞻项不赚反亏**：3 哨兵上 γ0=0 → 0.738/0.863/1.028 vs 默认 0.5 →
  0.777/0.870/1.025（幅度在种子噪声内）。起作用的是结构（驻留+分相位
  着色），不是权重——与 ZAC_new 的 w_batch 平坦现象同款；
- 分相位 vs 混合着色（A3'）：qft_n29 0.777 vs 0.763，噪声内持平；分相位的
  价值在记账诚实（跨相合色物理上不存在）。

## 4. 配套：正确性装置（三个改进的落地保障）

**七道补丁**（对抗审计后逐条落地）：菜单硬排除（闲人+同轮他人座位）、
`_repair_placements` 终检安全网、驻留者保座朝向（`_pair_seats`：配对含
自己座位时不动、搭档去另一座）、依赖账本补丁、流契约断言（长度 2n+1/
拷贝不变式/单射）、匹配修复（scipy "full" 只保小侧全覆盖 + 顺延预扩容）、
RNG 隔离 + 白名单消费断言（任务单里未认识的键直接报错——本次实战逮住
fitness_mode 漏项，避免了一次静默空实验）。

**verify_batches.py 8 查**（独立回放，不信任编译器自述）：批内兼容 /
位置连续 / 时序（取放语义，镜像 router 的 drop-after-pickup）/ 门邻接 /
**座位独占时间线**（同时刻整批结算——ZAC 两段式搬运的零驻留中转曾使
逐事件处理全部误报）/ 1q 位置一致 / **门账本**（与内嵌重综合门列表对账；
直读 QASM 会差在共享重综合层，ZAC 真值 4 电路同差异实证）/ 门-搬运互斥
（原子粒度）。**ZAC 原版 18/18 全过证校验器正确；7 类损坏注入全部抓到；
ZAC_zzx 全部输出全绿。**

## 6. 边界与 v1.1 方向

- **链式电路的几何铁律**：新原子必须与驻留者同排落座（配对座位同行），
  触发"同终点⇒必须同起点"的 y 维冲突——驻留者只要动、两腿必分两批。
  破法是**预取**（下轮搭档提前入场占位），v1.1 首选；
- 判分模型 idle 项被注释（simulator.py:77 → 恒 1）：驻留闲放零保真度
  代价（与全系统一致沿用）；1q=0.625μs/52μs 内部不一致同理；
- stay_horizon 在本套件不 binding（实测 inter-use 仅 1-2 轮）；
- 其他 v1.1：rollout 前瞻档、多种子取优、与 ZAC_new-B 的互补融合
  （ising_n98 类超宽层交给 B 式着色放置）。
